# The Dispatch app (running and syncing)

Sessions are detected by the one hook entry Dispatch puts into each agent (`hook.py`; `dispatch hooks status` says whether it is there and whether Codex trusts it, `dispatch hooks sync` puts it right); the records are in `~/tasks/.dispatch/sessions`, so do not delete that folder. When the board says `Dolt server unreachable`: on a connected computer run `bd dolt start` (a LaunchAgent also starts it every 2 minutes); on the hub its own LaunchAgent starts it, so do not run `bd dolt start` by hand there. Updating the app itself: Settings → Version and updates, or `dispatch update apply`.
- Across machines: tasks, sessions and progress are not synced; each machine has its own board, and another one's is read through the multi-machine connection (`--host`). Knowledge about the person (preferences, wiki, rules GLOBAL/FACTS/PROFILE/artifact, the skill pool, sub-agent definitions) is in `~/.dispatch` and stays the same on both by itself: committed a few seconds after a write, and the resident chatd pulls and merges from the online machines in hosts.json every 5 minutes; when both changed the same spot, both versions stay (the other as `<file>.conflict-<machine>`) and a notification goes out. `dispatch knowledge status|sync` shows the state and syncs at once; `dispatch doctor`'s knowledge.sync warns after a day without sync.

### Agents reviewing each other (separate from the person's confirmation)
When finished work needs an independent check: `dispatch done <id> --reason "what was delivered and how it was checked" --verified --review-by claude-code`. This only records a review request; it starts no agent and does not count toward the person's Waiting for you dot.
After another agent checks it: `dispatch review <id> --verdict pass --reason "what was checked, the result, the tests or files as grounds"`; with problems use `--verdict changes` and the task reopens. Use your own real `BEADS_ACTOR`; whoever did the work cannot record their own review as passed; the verdict goes into the task's activity first, then the review label is updated.
