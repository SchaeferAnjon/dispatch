# Discussing, then splitting the work (dynamic workflows, `dispatch discuss` / `dispatch split`)

**Use it only when the person explicitly asks in the current conversation to "have a few agents discuss it"; never start one yourself**: every participant costs the tokens of a whole new session. Handing out work (`dispatch agent start`) is not limited by this.
When it is unclear how to split something and a few models should each speak once before the work is divided:
```bash
dispatch discuss <id> --with codex,claude:haiku,pi [--leader pi] [-q "what they should decide"] [--rounds 2] [--conclude]   # headless: claude -p / codex exec / pi -p in parallel; the CLI feeds the thread into the prompt and writes replies as comments marked 【讨论】; a reply of SKIP does not go on the board
dispatch discuss --topic "an idea" [-P project] --with …                                          # without a task: makes a task marked 【讨论】 to hold it
# --timeout is each member's limit per round in milliseconds (default 600000); seconds work too (numbers under 10000 count as seconds); usually not needed. Discuss with pictures with --image <path>, repeatable.
dispatch discuss-judge <id> --with …    # a dry run of the judge: who would be called next round and why (no model is called)
dispatch discuss-conclude <id>          # writes (overwrites) the conclusion: the task description has exactly one `## 讨论结论` section (the marker is the same in every language)
dispatch discuss-doc <id>               # wraps up: writes the conclusion, then a document (background/conclusion/plan/steps/risks/acceptance) into the description; repeatable
dispatch split <id> --to codex:"subtask title|notes" --to claude:"…" [--no-start]           # your call: makes subtasks from the discussion (parent-child, with discussed-in:<id>) and starts the matching agents; the parent keeps a 【分工】 record
```
`--leader kind[:model]` names the leader (added by itself when not in --with): it speaks last each round and sums up, and its model writes the conclusion and the document (the description records `领队：kind:model`, and the interface hands work to it by default). Each member's session is kept in `~/tasks/.dispatch/discussions/<id>.json`, and the next round's `--resume` feeds only the new messages (`--fresh` starts over); personas and length rules are in `dispatch settings` (discuss_rules, discuss_persona_claude/codex/pi) and go into the system prompt. Once members have spoken, each round first passes a judge that calls no model: it reads only messages since the last judgement; `@codex` / `@claude (opus)` / `@opus` calls whoever is named; a member mentioned in someone's challenge or reply to their view (a question mark, "wrong", "disagree", "what X said", "X's plan" …) is called to answer; only a sentence of yours naming nobody, or `@everyone`, calls all, and `--everyone` skips the judge. Members not called start no process that round and catch up on what they missed when next called. pi always discusses with `--thinking low` (GLM-type models think longer than they speak by default). Conclusions are no longer written every round; when two rounds in a row bring nothing new (all SKIP or one sentence), the CLI suggests wrapping up. `--tui` or `--host` opens a conversation in Dispatch on that computer for each member (claude and codex only, run with permissions skipped). Subtasks each run `dispatch done`; whoever started it wraps up the parent. Interface: the side bar's Discussions page (`#/discuss/<id>`) lists all discussions, conclusion and document on the left, the group chat on the right; the "Discuss an idea" dialog draws typing bubbles live (`dispatch discuss-live <id>` reads `<id>.live.json`); the task detail has a "Discussion and split" block.
