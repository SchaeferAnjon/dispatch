# Claude / Codex paths, loading and sizes at a glance

Platform mechanisms change. Probe the current environment and this machine's rules first; for writes or size limits, check the current official docs or the local tool's own output first, and never treat this table as permanent fact.

## General principles

- Tell three kinds of file apart: rules people maintain, the agent's automatic memory, and machine-generated history or indexes. They do not share one set of write rules.
- `MEMORY.md` is only a file name; it does not mean the same thing on every platform. A size threshold belongs to one platform and one kind of file.
- The real rule file may be CLAUDE.md, AGENTS.md, an override, an import or a symlink; the workspace's declaration and the real load chain decide.
- Finding several platforms' folders does not mean every platform is in use. Audit only the platform running now and the installs the person explicitly includes.

## Claude Code

| Purpose | Usual path / rule |
|---|---|
| User instructions | `~/.claude/CLAUDE.md` |
| Project instructions | `./CLAUDE.md`, `./.claude/CLAUDE.md`, `CLAUDE.local.md` |
| Path rules | `.claude/rules/**/*.md` |
| Automatic memory | `~/.claude/projects/<project>/memory/` |
| Automatic memory index | `MEMORY.md` in that folder |
| Skills | `~/.claude/skills/<name>/SKILL.md` or the project's `.claude/skills/` |

What the official docs say now:

- CLAUDE.md is loaded in full, but the advice is to stay under about 200 lines; longer files cost attention and are followed less. This is a quality budget, not a hard cut-off.
- Claude's automatic memory `MEMORY.md` loads only its first 200 lines or 25 KB (whichever comes first) at session start; topic files are read when needed. This hard limit belongs to Claude's automatic memory only, not to Codex's generated memory.
- Claude reads CLAUDE.md natively. A project that already has AGENTS.md can share one source by import or symlink; the project's rules decide the direction, never flip it on your own.

## OpenAI Codex

| Purpose | Usual path / rule |
|---|---|
| Codex home | `$CODEX_HOME`, by default `~/.codex` |
| Global instructions | `$CODEX_HOME/AGENTS.override.md`, else `AGENTS.md` |
| Project instructions | from the project root to the current folder, level by level: `AGENTS.override.md`, `AGENTS.md`, the configured fallback |
| Global skills | `$CODEX_HOME/skills/<name>/SKILL.md` |
| Project skills | the project's `.codex/skills/<name>/` (check the current Codex version and environment) |

What the official docs say now: the merged project instruction chain is at most 32 KiB by default, set by `project_doc_max_bytes`; instructions closer to the current folder load later. Check overrides and fallbacks; do not look only for AGENTS.md in the root.

Some Codex environments also have `~/.codex/memories/`, rollout summaries or Chronicle-derived indexes. These may be generated by the host's pipeline:

- Read the memory instructions the environment gives first; without explicit authorization they are read only.
- Do not edit a generated `MEMORY.md`, `memory_summary.md`, `raw_memories.md` or rollout summary directly.
- When the person explicitly asks to update memory and the environment allows it, use only the correction input that Codex environment prescribes, or control generation and use through the official `/memories`, settings and `memories.*` configuration, then wait for the host's consolidation. Set no file size targets, compaction candidates or project-level gates for generated memory.

Treat files such as `TEAM_GUIDE.md` or `.agents.md` as instruction files only when they appear in Codex's fallback configuration.

## Other Agent Skills platforms (Qoder, Kimi Code, iFlow, CodeBuddy, Cursor, Gemini CLI …)

Agent Skills is an open standard (opened by Anthropic in December 2025); about 40 products can use this skill's distribution format. Platforms other than Claude Code and Codex have no table of their own here; probe them the general way:

1. **Rule files**: in the project root and the folders above, look for `AGENTS.md` (the de facto cross-platform standard), `CLAUDE.md`, and the platform's own forms (`.cursor/rules/`, `.cursorrules`, project instructions in the platform's settings). Which one is really loaded is decided by the platform's docs and diagnostics, not by guessing.
2. **Three-way classification**: put every knowledge file you find into one of three kinds: rules people maintain, the agent's automatic memory, machine-generated history or indexes. When unclear, treat it as machine-generated (the most cautious choice).
3. **Memory boundary**: on an unknown platform without an official control for memory, memory is read only; never carry another platform's size thresholds or write rules over.
4. **Fallback use**: when the host does not support Agent Skills, this skill still works: give the whole SKILL.md to the agent as a rule file or a chat instruction and follow the references as needed; the boundaries stay the same.

## Living side by side

1. List the platform folders that really exist and each skill's realpath.
2. Check whether skills of the same name are symlinks to one source, copied installs, or overridden by a higher-priority version.
3. Change only the authoritative source; a copied install needs an explicit sync mechanism, never assume it updates itself.
4. Symlinks may not work on Windows or in restricted environments; a project may use imports or generated mirrors as long as the local rules say so and a consistency gate exists.
5. Verify loading, not just that the file exists: use the platform's instruction or skill list, `/memory`, status or an equivalent diagnostic.
