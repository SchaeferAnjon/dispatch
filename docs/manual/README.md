# Dispatch 用户说明书

> 这一页解决什么：先弄清 Dispatch 是什么、适合谁、不做什么，再决定从哪一章读起。整本说明书可以用左上角的搜索框全文检索。

Dispatch（调度台）是一个装在 Mac 上的**本地 Agent 工作台**。你在终端或编辑器里像平时一样用 Claude Code、Codex、pi、ZCode、Gemini CLI、OpenCode、Hermes 这些编程 Agent；Dispatch 只读它们已经写在本机的记录，按**项目**把每一段会话、每个任务和每项成果摆到一个台子上：谁在等你、谁在跑、做到哪了。看到 Agent 在等你，就在电脑或手机上直接回复原会话。

当前版本 v0.7.29，支持 macOS 14 及以上，开源（MIT）。官网与演示视频在 <https://schaeferanjon.github.io/dispatch/>，源码在 <https://github.com/SchaeferAnjon/dispatch>。

## 它做什么

- **只读本机记录**：Claude Code 与 Codex 的转录文件（包括 VS Code 扩展里开的会话）、pi 的会话文件、OpenCode、ZCode、Hermes 的数据库。不需要 API Key，也不需要先建任务板就能看会话。
- **按项目组织**：会话按工作目录归到项目；任务和成果挂在会话上；项目页就是一个项目的全部记录（回顾、会话、任务、成果、文档、知识库）。
- **回复回到原会话**：从工作台、「等我」或手机进入会话直接回，消息投递到那个终端里的原会话。正在跑就排队，排错了能撤回。
- **任务由 Agent 自己记**：每个新会话开头自动收到身份、本项目任务和相关知识；Agent 用 `dispatch begin / log / done` 记任务，用 `dispatch wiki` 记坑。你不用在界面里逐个点完成。
- **两台电脑一份数据**：任务板、规则、技能同步；项目连同未提交改动、Git 历史和正在跑的会话可以一键搬到另一台。
- **手机**：通过 Tailscale 访问同一套界面；通知走 ntfy、Bark 或系统通知；需要时用 noVNC 看电脑屏幕。
- **不额外调模型**：界面本身不调用任何模型。只有「总结」类功能（会话总结、项目现状、讨论结论、洞察报告、记忆总览、语义搜索）会把摘录交给你在设置里选定的模型。这些用途默认是开着的，可以在 [设置](14-settings.md) 里逐项关掉；详见 [已知限制](26-limits.md)。

## 适合谁

- 同时开着好几个终端、好几个 Agent，经常忘了哪个在等确认、哪个项目做到哪了的人。
- 想让 Agent 自己记任务和踩坑记录，而不是自己手动维护看板的人。
- 有两台 Mac（比如一台常驻、一台随身），希望任务板和规则只有一份的人。
- 出门时想在手机上看进展、回一句话、按一下确认键的人。

## 它不是什么

- **不是另一个 Agent**：Dispatch 不生成代码，也不代替你和 Agent 对话。它只是看和转发。
- **不是云服务**：所有数据都在你的 Mac 上。手机访问走 Tailscale 私网，不暴露到公网。
- **不是通用项目管理软件**：任务板（Beads）是给 Agent 记的，字段和流程围绕「Agent 做了什么、你要做什么」设计。
- **不读 ChatGPT 网页会话**，也拿不到原 Agent 应用的「已读」回执（只能在你回复之后清掉未读）。
- **目前只有 macOS 版**。界面层是 Tauri + React，逻辑在 Python CLI 里，移植是可能的，但还没做。
