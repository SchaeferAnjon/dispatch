# 规则与资料

> 这一页解决什么：所有 Agent 的共同规则怎么写、怎么同步、怎么检查；常用资料、密钥、各 Agent 的记忆、「关于我」都在这一页管。

页面顶部四个模式：**Agent 规则**、**常用资料**、**Agent 记忆**、**关于我**。每个模式都有「改的是 <机器>」提示，侧栏选了另一台就改那台。

## Agent 规则

### 思路

`~/.agents/rules/GLOBAL.md` 是共同规则的**唯一来源**。同步时它被写进每个 Agent 入口文件里的一个托管块：

```
<!-- BEGIN DISPATCH GLOBAL RULES ... -->
…GLOBAL.md 的内容…
<!-- END DISPATCH GLOBAL RULES -->
```

入口文件比如 `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、pi、Gemini、OpenCode 的对应位置。托管块外面是该 Agent 自己的特殊配置。改规则改 GLOBAL.md，再同步；编辑入口文件时托管块显示成一行占位，不会被误改。

### 页面

- **作用范围**：全局规则，或选一个检测到的项目（把项目的 AGENTS.md / CLAUDE.md 与继承的全局规则一起看）。
- **同步按钮**：「共同规则已同步」或「同步共同规则 · N 个待更新」；「尚未配置共同规则」时先跑首次设置第 5 步。命令行 `dispatch rules status|sync`。
- **左侧文档列表**：「所有 Agent 的共同规则」（GLOBAL.md）、各 Agent 入口、项目规则、被引用的文档；标注未创建、被覆盖、引用文档、项目规则、全局入口。右键可用编辑器打开、在访达中打开、复制路径、复制内容。
- **右侧**：文档内容（Markdown 渲染）、行数和大小。「编辑」进入编辑；「检查」做本地静态检查：重复、潜在冲突、失效引用、作用范围、长度、可移植性、循环引用、版本不一致。检查**不调用模型，也不上传文档**。
- 编辑时：「检查并预览差异」→ 「应用 N 个文件的修改」。保存前会重检所有文档版本；改的是 GLOBAL.md 时所有托管副本一起预览、保存；保留恢复版本（「恢复上次保存」）。文件被其他程序改过时拒绝覆盖。
- **检查建议**：每条带类型、位置、说明和建议；「复制深度审查指令」把所选上下文交给你自己的 Agent 做语义审查。「潜在冲突」是静态检查结果，不是完整语义证明。
- **引用关系与检查依据**：这份文档引用了谁，以及各 Agent 官方文档链接。

修改规则不会立即重载已有 Agent 会话，新开会话才生效。

## 常用资料

三块：

- **密钥与 API**：`dispatch env` 的界面。密钥存在 `~/.config/dispatch/env`（仅本人可读），不进任务板、不进知识库、不进 Git。每条有名字、用途、可选的项目（只属于某个项目时，Agent 只在该项目的会话里看到它，项目页也会列出）、掩码后的值。操作：显示、复制、编辑、复制取用命令（`dispatch env get 名字`）、删除（点两次确认，值找不回来）。Agent 在会话开始只看到变量名和用途，需要时自己取值，不用你每次重贴 Key。
- **服务器与数据库**：全局 `~/.agents/rules/FACTS.md`，记机器、云服务、数据库和账号用途，`## 通用` 每个会话注入，密码和 Token 放到密钥里。项目自己的短事实在项目页「文档」标签的 FACTS.md。
- **Obsidian 资料库**：列出所选电脑上检测到的资料库，「在 Obsidian 打开」「复制路径」。只读元数据，不移动或上传笔记。

## Agent 记忆

每个 Agent 自己跨会话积累的长期记忆（Claude Code、Codex、ZCode、Hermes 的记忆文件），按 Agent 和项目分组，页面只读。

- 左侧树：Agent → 项目 → 条目，「索引」标记项目的索引文件，「过期」标记项目目录已不存在的，可「归档」到同目录的 `archived/` 文件夹。
- 右侧：没选时是**总览**（用总结模型写的总体和各项目一句话，有缓存，「重新总结」重写）；选项目看该项目的条目；选条目看正文，可「复制路径」「用默认应用打开」「归入关于我」（把这条追加到「关于我」，之后所有 Agent 都会看到）。

命令行 `dispatch memories list|show|archive|summary`。打开这页会自动请求一次总览（会调模型），见 [已知限制](26-limits.md)。

## 关于我

`~/.agents/rules/PROFILE.md`：关于用户本人的档案，分现状、将来会发生的事、已发生，由 Agent 自动维护（`dispatch profile add|upcoming|done`），`dispatch prime` 会注入。这里可直接编辑；「重新盘点」让 Agent 实测各机器现状并改写「设备与服务现状」一节（会调模型）。
