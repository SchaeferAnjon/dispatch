# 统计与额度

> 这一页解决什么：各 Agent 的额度用了多少、什么时候重置；历史用量按 token、消息、工具、模型、项目怎么分布；跨 Agent 的复盘洞察在哪看。

![额度](../assets/shot-quota.png)

侧栏「统计与额度」进入，页面顶部两个标签：**额度概览**、**使用统计**。选了哪个每台设备记住。侧栏按机器筛选时，这里只算那台机器。

## 额度概览

每个 Agent 一张卡：头像、名字、机器（同一账号在两台机器上会写「+ <机器> · 同一账号」）、套餐（Pro、Max、Plus、Team 等），下面是各时间窗的用量条：标签（如 5 小时、7 天、某个模型）、已用百分比、「Nh 后重置」。70% 以上变黄，90% 以上变红。卡片底部是更新时间（超过 10 分钟会提示数据较旧）和「数据来源」折叠。

- 百分比表示**已使用**额度；相同账号在不同机器上的额度共享，不累加。两边数字对不上时会提示「和 <机器> 上不是同一个账号」，也可能是其中一份数据过期。
- 数据来源：Claude Code 走官方用量接口（读本机的登录态，只读不外传），Codex 和 ZCode 读各自的本地状态。缺失或过期的会标明，不推算成零。
- 「刷新额度」重新读一次；「暂无额度数据 · N 项」展开没拿到数据的 Agent。
- 顶部栏和菜单栏图标里显示的是本机的这几条。

## 使用统计

工具栏：按 Agent（全部或单个）、时间范围（7 天、30 天、90 天、一年、全部）、按 token 或按消息。有两台机器且没筛选时会写「A + B」，表示两台的统计相加。

内容从上到下：

1. **洞察卡**（见下）。
2. **四个数字**：总 token（输入、输出、缓存读、缓存写、思考）、消息数（会话数、子 Agent 占比）、活跃天（当前连续、最长连续）、工具种类（活跃时段数或起始日期）。
3. **谁烧的**：各 Agent 的 token 占比条。
4. **活动热力图**：GitHub 风格的日历，颜色深浅是当天 token 或消息数。
5. **什么时候在干活**：周 × 小时的网格，写出最忙的时段。
6. **最近 N 天**：每天的柱状图，按 Agent 叠放。
7. 排行：最常用工具、模型（次回复）、最常用技能（Skill 工具或 / 命令）、派过的子 Agent、项目：谁最烧 token。

token 数来自各 Agent 自己的记录：Claude Code 每次 API 回复的 usage（按 requestId 去重），Codex 每轮的累计 token_count，ZCode 每条消息的 tokens。这里不算钱，你用的是订阅，看额度页就够了。第一次打开需要索引全部聊天记录，可能要等一分钟。

## 洞察

统计页顶部的卡片是跨 Agent 的复盘，相当于 Claude Code 自己的 /insights，但覆盖所有 Agent 的会话：

- **报告**：模型写的一份报告（最近 N 天），分节展开，「打开完整页面」看 HTML；可以手动「生成」（一般 1 到 3 分钟）或设定每 7 / 14 / 30 天自动生成；历史报告可切换。
- **信号计数**：正则数出来的行为信号：纠错多、上下文溢出、工具报错、没上板、超长，按 Agent 分。
- **主动洞察**：按会话盯着的告警，新的会在工作台和系统通知里提醒；「看会话」跳过去；「都看过了」标记这批。
- **派 Agent 去改进**：把 friction 和 suggestions 两节交给一个 Agent 落地成规则或技能的修改。

命令行：`dispatch insights`（信号）、`dispatch insights report|list|show|open|schedule`。洞察报告用的模型见 [已知限制](26-limits.md)。
