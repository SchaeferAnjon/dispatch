# 核心概念

> 这一页解决什么：把 Dispatch 里反复出现的十来个词一次讲清。读完这页，其他章节里的按钮名就都能对上号了。

Dispatch 只有一条主线：**项目里发生会话，会话延伸出任务，任务汇成成果。** Agent 在下面干活，你在上面看、回复、派活。

## 项目

会话按**工作目录**归到项目：

1. 手动关联过的以手动为准（会话右键 → 「关联项目…」）。
2. 家目录本身的会话不归任何项目。
3. 「工作区根目录」（设置里，默认 `~/Projects`）下的直接子文件夹各算一个项目。
4. 其他位置按 git 仓库根目录归项目，没有仓库就按所在文件夹。
5. 路径里出现任务板已知的项目名时也会归过去。

只有**有任务、有成果、或手动关联过**的才算正式项目；其余只是「目录」，在项目页底部的「其他目录与未归类」里。项目可以收藏（置顶）、归档（从工作台和列表隐藏，随时找回）、双击标题改显示名；这些状态存在共享任务板上，两台电脑一致。

## 会话

一段会话就是一个 Agent 在一个目录里的一次完整对话。Dispatch 从 Agent 自己的记录里读出它的标题、目录、分支、每一轮对话、工具调用、改过的文件、图片和产物。会话有几种状态：

- **在跑**：Agent 正在工作，列表里绿色高亮，会话页实时跟读。
- **等你**：Agent 停下来等你的回复或确认，工作台和「等我」里会出现。
- **未读回复**：Agent 答完了、你还没看到最新一轮，有蓝点。读到最新后自动移出；在原终端里继续回复也会被识别。
- **追踪中**：你收藏的会话，固定在工作台顶部，不会自动归档。
- **已归档**：手动归档，或超过设置里的天数没有活动。
- **定时或脚本**：不是你在终端里开的（定时任务、脚本、别的 Agent 通过程序接口起的），不进「等我」、不发通知。

会话的**来源**会标出来：终端、桌面端、VS Code、SDK、定时任务、Telegram 等。

## 任务

任务存在中央任务板（Beads，目录 `~/tasks/.beads`）上。**任务由 Agent 自己记**：明白要做什么后 `dispatch begin`，记进展 `dispatch log`，收尾 `dispatch done`。你也可以在界面里新建（<kbd>⌘T</kbd>）、编辑、拖动。任务有：

- 状态：待办、进行中、阻塞、搁置、已完成。
- 优先级 P0（最急）到 P4（最低）。
- 验收标准：一行一条的 `- [ ]` 清单，谁勾的会署名（「你核对」「自审 · Agent」「复核 · Agent」）。
- 完成说明：`dispatch done --reason` 写的交付与验证。
- 与会话的关系：**只认** `session-origin:`（发起会话）和 `session:`（参与会话）标签。对话里提到任务 ID、同一个 Agent、同一个目录都不算归属，只作为「对话中提到过」的线索。
- 任务编号：Beads 自动生成，前缀是板的名字（如 `task`），后面三位随机，没有含义。

任务可以移到**回收站**（可恢复，保留描述、评论和依赖），已完成很久的可以**归档**（不进已完成列、不计数）。

## 成果

成果是独立的一条记录（标签 `dispatch:outcome`），写明交付了什么、在哪看，可以关联多个任务和会话。它不进普通任务计数，也不进脉络图。在项目页「成果」标签登记或编辑；Agent 也可以用 `bd create` 加标签登记。历史任务的完成说明单独保留，不会自动变成成果。

## 等我

「等我」只放需要你动手的事，红点和系统通知只算前两类：

- **未读回复**：Agent 答完等你看。正在跑的会话不算未读。
- **等待确认**：Agent 停在权限、信任目录之类的确认框上（只有接入事件上报的会话，也就是在 Herdr 里跑的，会出现在这里）。
- **只能你做**：Agent 遇到只有你能做的事（发邮件、付款、登录、当面演示、做决定），用 `dispatch need-you` 记成一条任务，显示在项目页「任务」标签的「只能你做」列，做完打勾。

被卡住的任务、Agent 互审、定时会话都不计入红点。

## 知识库

所有 Agent 共用的知识库，存在任务板的 memory 里。四种条目：

- **坑**（pit）：现象 + 解法。
- **做对**（win）：做法 + 为什么对。
- **复盘**（retro）：`dispatch done --retro` 自动生成，含技术、做对、做错。
- **做法**（howto）：一套可复用的步骤。

会话启动时 `dispatch prime` 只注入当前项目和通用条目；其余 Agent 用 `dispatch wiki search` 按需查。项目页「知识库」标签只看本项目的。

## 规则

`~/.agents/rules/GLOBAL.md` 是所有 Agent 的共同规则，唯一来源。「规则与资料」页把它同步成每个 Agent 入口文件（`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md` 等）里的一个**托管块**，并做静态检查（重复、潜在冲突、失效引用、长度）。改规则改 GLOBAL.md，然后同步；直接改入口文件里的托管块会被下次同步覆盖。

同一页还管「常用资料」（服务器、数据库、Obsidian 资料库）、「密钥与 API」（`dispatch env`）、各 Agent 的「记忆」和「关于我」（`~/.agents/rules/PROFILE.md`）。

## 技能池

技能是带 `SKILL.md` 的目录，统一放在技能池 `~/.cc-switch/skills`。「技能」页显示每个技能挂给了谁（Claude Code、Codex），能在应用里改 SKILL.md、新建、从 GitHub 导入。挂载 = 软链到 Agent 的技能目录，新会话生效；卸载只删软链，本体不动。

## 两台电脑与枢纽

第一台完成首次设置的电脑是**枢纽**：任务板、规则、技能都在它上面。第二台在首次设置第 3 步「接入」它，之后每 2 分钟双向同步任务板（Dolt 远程 API），规则和技能也保持一份。侧栏顶部可按机器筛选。项目和会话可以在两台之间**迁移**。详见 [两台电脑](21-two-macs.md)。

## Herdr

Herdr 是终端里的 Agent 多路复用器，靠 tmux 在后台常驻。Dispatch 通过它：

- **派活**：在新标签里起一个 Agent，认领任务，发第一条提示词。
- **回复原会话**：把你在 Dispatch 或手机上打的字投递到 Herdr 里那个 Agent 的输入框；在跑就排队，或先 Esc 打断。
- **判断状态**：只有 Herdr 里跑的会话有标签标题、在跑 / 等你的判断、手机端回复和确认框按键。

在 Warp、iTerm、Terminal 或 VS Code 里跑的会话可以「接进 Herdr」（`dispatch adopt`）：停掉空闲的原进程，在 Herdr 新标签里 `--resume` 同一段会话。

## 机器、Agent 与「你」

- **机器**：`~/tasks/.dispatch/hosts.json` 里的每台 Mac，设置 → 机器里能改名、重新检测、删除。
- **Agent**：Claude Code、Codex、pi、ZCode、OpenCode、Hermes 各算一个身份；同一 Agent 的多个会话共用一个头像。
- **你**：以本机用户名为准，任务里的留言、验收勾选都会署上。
