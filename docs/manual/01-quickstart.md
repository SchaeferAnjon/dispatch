# 五分钟上手

> 这一页解决什么：从下载到看见第一个项目的完整步骤，包括 Gatekeeper 放行、首次设置的八步，以及第一次看到工作台之后先做的三件事。

## 0. 准备

- 一台 macOS 14 或更新的 Mac。
- [Homebrew](https://brew.sh)：首次设置会用它安装 Dolt、Beads、Herdr、tmux。没装的话，首次设置第 1 步会给出安装命令。
- **Python 3.9 或更新**。装过 Xcode 命令行工具或 Homebrew 的 Mac 都有；Dispatch 会自己找（Homebrew 的优先，其次系统自带的）。都没有时应用不会是空白，而是显示「环境检查」页，列出缺什么，并给出可复制的安装命令（`brew install python@3.12` 或 `xcode-select --install`）。
- 至少装了一个 Agent（Claude Code、Codex、pi、ZCode、Gemini CLI、OpenCode、Hermes 之一），并且在本机跑过一两次，这样 Dispatch 一打开就有东西可看。

## 1. 安装

1. 到 [Releases](https://github.com/SchaeferAnjon/dispatch/releases/latest) 下载 `Dispatch-<版本>-macos-apple-silicon.zip`（目前只发布 Apple 芯片包，Intel 机器需要自己从源码构建，见 [已知限制](26-limits.md)）。
2. 双击解压，把 **Dispatch.app** 拖进「应用程序」。
3. 这个包没有 Apple 开发者签名，第一次打开会被 Gatekeeper 拦下。任选一种放行：
   - 打开「终端」，粘贴：
     ```sh
     xattr -dr com.apple.quarantine /Applications/Dispatch.app
     ```
     然后再打开应用；
   - 或者先双击一次被拦，去 系统设置 → 隐私与安全性，拉到最下面点「仍要打开」。
4. 打开后自动进入**首次设置**。

## 2. 首次设置（八步，后三步可选）

首次打开会走一遍。每一步都能重跑；右上角「跳过，以后不再提示」可以先进工作台，之后从 设置 → 首次设置 → 「打开首次设置」再回来。页面顶部会显示这台电脑的名字和 Tailscale 或局域网地址。

### 第 1 步：装依赖

页面列出六样东西，找到的打 ✓，缺的打 ✗：

| 名称 | 作用 | 必需 |
|:--|:--|:--|
| brew | macOS 的包管理器，下面几样都靠它装 | 是 |
| dolt | 任务板的数据库（带版本历史，能在两台电脑之间同步） | 是 |
| bd | 任务板本身（Beads），Agent 用它记任务 | 是 |
| herdr | 终端里的 Agent 多路复用器，Dispatch 用它派活给 Agent | 是 |
| tmux | 让 Herdr 在后台常驻，Dispatch 随时能把活派给 Agent | 是 |
| tailscale | 两台电脑不在同一 Wi‑Fi 时互相访问；只有一台电脑可以不装 | 否 |

- 没有 Homebrew 时，页面给出一行安装命令和「复制」按钮：在终端里粘贴运行（会要管理员密码），装完回来点「重新检测」。
- 有 Homebrew 时，点「装上 dolt、bd、herdr…」，Dispatch 用 brew 逐个安装，可能要几分钟。失败的会显示原因和可以在终端里手动跑的命令。

### 第 2 步：终端命令

点「建立 dispatch 命令」，把应用自带的 CLI 链接到 `~/.local/bin/dispatch`。之后终端里直接能敲 `dispatch`，Agent 的 hook 也靠它；应用更新时 CLI 一起更新。

手动做也行：

```sh
ln -sf /Applications/Dispatch.app/Contents/Resources/cli/dispatch.py ~/.local/bin/dispatch
```

确认 `~/.local/bin` 在你的 PATH 里。

### 第 3 步：任务板

二选一：

- **「只有这一台，或这是第一台」**：点「新建任务板」，在 `~/tasks/.beads` 新建一块板，这台电脑成为其他电脑接入的**枢纽**。
- **「已有一台电脑装了 Dispatch」**：填那台的 `用户名@地址`（可以从 Tailscale 列表里选一台，再补上用户名），填一次那台的登录密码（只用一次，不保存，用来放公钥），点「打通并接入」。前提是那台已经跑过首次设置并打开了「远程登录」。不想给密码，可以点「让本机 Agent 代劳」，Dispatch 会起一个 Agent 在终端里帮你完成。

接入后页面会显示「已接入 <名字>，每 2 分钟双向同步」，并且可以「检查一次」枢纽能否反向连回本机（枢纽合并这台的会话需要这个）。

### 第 4 步：Agent

页面检测本机装了哪些 Agent，默认勾上找到的。勾选的 Agent 会收到同一份规则；Claude Code 还会装上 hook（会话状态、任务板摘要、编辑互斥、额度）。VS Code 里的 Claude Code / Codex 扩展用的是同一份记录和同一套 hook，勾上对应的 Agent 就够了，它们的会话会标成「VS Code」。点「就用这些」。

### 第 5 步：规则与技能

点「准备规则并同步」：

- 还没有共同规则时，如果有 `CLAUDE.md` / `AGENTS.md`，导入它作为起点；没有就用一份精简模板，写到 `~/.agents/rules/GLOBAL.md`。
- 接入了枢纽时，从枢纽复制 GLOBAL.md 和技能池。
- 然后把 GLOBAL.md 同步到每个 Agent 的入口文件（托管块），并把技能池挂到 Claude Code 和 Codex 的技能目录。

页面列出每个 Agent 的入口路径和同步状态。

### 第 6 步：模型与总结（可选）

Dispatch 自己不带模型。会话总结、项目现状、记忆总结、洞察报告、语义搜索这些功能要把对话摘录或文档片段发给一个模型才写得出来，所以在你选之前一律不发。三种选法：

- **先不用**：什么都不发，界面照常可用，只是没有自动写的总结。
- **用 Claude Code 订阅**：在这台电脑上跑 `claude -p`，不需要 API Key，算在你的订阅额度里。
- **用 API Key**：选一家供应商，填 Key（只存在这台电脑的 `dispatch env` 里），按它的价格计费。

选了后两种，再勾要用它做什么。之后都能在 设置 → 总结 里改。

### 第 7 步：手机与通知（可选）

点「开启手机访问」，这台电脑会常驻一个网页服务并开机自启；出现二维码后用手机相机扫一次就记住了。没有 Tailscale 时要勾「允许局域网」手机才连得上。推送到手机的通知（Bark / ntfy）在 设置 → 手机通知 里配，见 [手机](20-phone.md)。

### 第 8 步：审查优化（可选）

选一个带命令行的 Agent，点「派它审查并优化」：它会读这台电脑上所有 Agent 共用的规则和技能，先做减法（删掉为老模型补的行为规则、逐步菜谱、和全局重复的内容），保留架构约束、安全边界和项目知识，然后直接改好并同步。也可以「复制提示词」发给任意 Agent。一台电脑也值得做一次。

前五步都打勾后，底部「完成，进入工作台」才可点。

## 3. 第一次看到工作台后先做的三件事

1. **开一段会话，看它出现在台子上**。在终端里照常开 Claude Code 或 Codex（或者在 Dispatch 里按 <kbd>⌘N</kbd>「新建会话」选一个文件夹开）。回到 Dispatch 工作台，几秒内这段会话会出现在对应项目卡片的「在跑」里；Agent 停下来等你时会变成「等你」。新会话开头 Agent 会收到 `dispatch prime` 注入的一段摘要，这就是它知道任务板和知识库的方式。
2. **检查项目归类**。打开 设置 → 项目 → 「工作区根目录」，默认是 `~/Projects`：这些文件夹的直接子文件夹各算一个项目。你的代码不在那里的话，把根目录加进去（一行一个），否则会话会按 git 仓库根目录或所在文件夹归类，项目名可能不是你想要的。
3. **决定总结要不要开**。设置 → 会话 → 「总结用的模型」：选一个订阅模型（如 Claude Code 订阅的 haiku）或粘贴一个 API Key；下面的用途表逐项决定「会话总结」「项目现状」等要不要调模型。不想让任何内容出机器，就把它们都关掉。详见 [设置](14-settings.md)。

然后顺手看一眼：

- 左侧栏最下面的「总览」：每个页面一句话，点进去。
- 设置 → 手机访问：想在手机上用就扫这个二维码，见 [手机](20-phone.md)。
- 如果有第二台 Mac，见 [两台电脑](21-two-macs.md)。
