# Core concepts

> What this page is for: explain the dozen or so words that keep coming up in Dispatch, once and for all. After this page, the button names in every other chapter will line up.

Dispatch has a single storyline: **projects contain sessions, sessions grow tasks, tasks add up to outcomes.** Agents work below, you watch, reply and delegate from above.

## Projects

Sessions are grouped into projects by **working directory**:

1. A manual link wins (right-click a session → "Link project…").
2. Sessions in the home folder itself belong to no project.
3. Each direct subfolder of a "Workspace root" (set in Settings, `~/Projects` by default) counts as one project.
4. Anywhere else, the git repository root decides the project, or the containing folder if there is no repository.
5. A path that contains a project name the task board already knows is grouped there as well.

Only folders **with tasks, with outcomes, or manually linked** count as real projects; the rest are just "folders", listed under "Other folders and ungrouped" at the bottom of the Projects page. A project can be starred (pinned to the top), archived (hidden from the workbench and lists, recoverable at any time), and renamed for display by double-clicking its title; these states live on the shared task board, so both Macs agree.

## Sessions

A session is one complete conversation between one Agent and one folder. Dispatch reads its title, folder, branch, every turn, the tool calls, the files it changed, images and artifacts out of the Agent's own records. A session can be in several states:

- **Running**: the Agent is working, the row is highlighted green, and the session page follows along live.
- **Needs you**: the Agent has stopped and is waiting for your reply or confirmation, and it appears on the workbench and in "Needs me".
- **Unread reply**: the Agent finished answering and you have not seen the latest turn, marked with a blue dot. It clears once you read to the end, and replying in the original terminal counts too.
- **Tracked**: a session you starred, pinned to the top of the workbench and never archived automatically.
- **Archived**: archived by hand, or idle for longer than the number of days set in Settings.
- **Scheduled or script**: not something you started in a terminal (a scheduled job, a script, or another Agent starting it through the programmatic interface). These never enter "Needs me" and never send notifications.

A session's **origin** is labeled: terminal, desktop app, VS Code, SDK, scheduled job, Telegram and so on.

## Tasks

Tasks live on the central task board (Beads, in the folder `~/tasks/.beads`). **Agents record their own tasks**: once an Agent understands what to do it runs `dispatch begin`, records progress with `dispatch log`, and wraps up with `dispatch done`. You can also create (<kbd>⌘T</kbd>), edit and drag tasks in the interface. A task has:

- A state: open, in progress, blocked, deferred, done.
- A priority from P0 (most urgent) to P4 (lowest).
- Acceptance criteria: a `- [ ]` checklist, one per line, with a signature for whoever ticked it ("You checked", "Self-checked · Agent", "Review · Agent").
- A completion note: what was delivered and verified, written by `dispatch done --reason`.
- Its relationship to sessions: **only** the `session-origin:` (the session that started it) and `session:` (participating session) labels count. A task ID mentioned in conversation, the same Agent, or the same folder does not establish ownership, and only shows up as a "Mentioned in conversations" hint.
- A task number: generated by Beads, prefixed with the board's name (such as `task`) and followed by three random characters with no meaning.

A task can be moved to the **Trash** (recoverable, keeping its description, comments and dependencies), and a task finished long ago can be **archived** (out of the Done column and out of the counts).

## Outcomes

An outcome is a record of its own (labeled `dispatch:outcome`) that states what was delivered and where to see it, and it can link to several tasks and sessions. It does not count as an ordinary task and does not appear in the thread graph. File or edit one on the project page's "Outcome" tab; an Agent can also file one with `bd create` plus the label. Completion notes on older tasks are kept separately and never turn into outcomes automatically.

## Needs me

"Needs me" holds only things that need your hands, and the badge and system notifications count only the first two kinds:

- **Unread reply**: the Agent answered and is waiting for you to look. A running session does not count as unread.
- **Needs confirmation**: the Agent is sitting on a permission or trusted-folder confirmation box (only sessions that report events, meaning the ones running inside Herdr, show up here).
- **Only you can**: the Agent hit something only you can do (send an email, pay, sign in, demo in person, make a decision) and recorded it as a task with `dispatch need-you`, shown in the "Only you can" column on the project page's "Task" tab; tick it off when it is done.

Blocked tasks, Agent-to-Agent reviews and scheduled sessions never count toward the badge.

## Knowledge base

A knowledge base shared by every Agent, stored in the task board's memory. Four kinds of entry:

- **Pitfall** (pit): symptom plus fix.
- **Win** (win): what was done and why it was right.
- **Retro** (retro): generated automatically by `dispatch done --retro`, covering the technique, what went right and what went wrong.
- **How-to** (howto): a reusable set of steps.

At session start, `dispatch prime` injects only the current project's entries and the general ones; for the rest, Agents look things up on demand with `dispatch wiki search`. The project page's "Knowledge base" tab shows only this project's entries.

## Rules

`~/.agents/rules/GLOBAL.md` holds the rules shared by every Agent and is the single source. The "Rules & docs" page syncs it into a **managed block** inside each Agent's entry file (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` and so on) and runs static checks (duplication, possible conflict, dead references, length). To change the rules, change GLOBAL.md and then sync; editing the managed block inside an entry file directly gets overwritten by the next sync.

The same page also handles "Reference" (servers, databases, Obsidian vaults), "Keys and APIs" (`dispatch env`), each Agent's "Memory" and "About me" (`~/.agents/rules/PROFILE.md`).

## The skill pool

A skill is a folder with a `SKILL.md` in it, and they all live together in the skill pool at `~/.cc-switch/skills`. The "Skills" page shows which Agent each skill is mounted on (Claude Code, Codex) and lets you edit SKILL.md, create a skill, or import one from GitHub inside the app. Mounting means a symlink into the Agent's skill folder and takes effect in new sessions; unmounting only removes the symlink and leaves the skill itself alone.

## Two Macs and the hub

The first Mac to finish first-run setup is the **hub**: the task board, the rules and the skills all live on it. The second Mac joins it at step 3 of its first-run setup, after which the task board syncs both ways every 2 minutes (through the Dolt remote API), and the rules and skills stay as one copy. The top of the sidebar can filter by machine. Projects and sessions can be **moved** between the two. See [Two Macs](21-two-macs.md) for details.

## Herdr

Herdr is the Agent multiplexer in your terminal, kept resident in the background by tmux. Dispatch uses it to:

- **Delegate**: start an Agent in a new tab, claim a task and send the first prompt.
- **Reply to the original session**: deliver what you typed in Dispatch or on your phone into the input box of that Agent inside Herdr; if it is running, the message queues, or you can press Esc to interrupt first.
- **Judge state**: only sessions running inside Herdr get labeled tab titles, a running / needs-you judgment, phone replies and confirmation keypresses.

A session running in Warp, iTerm, Terminal or VS Code can be taken "Into Herdr" (`dispatch adopt`): the idle original process is stopped, and the same session is resumed with `--resume` in a new Herdr tab.

## Machines, Agents and "You"

- **Machine**: every Mac in `~/tasks/.dispatch/hosts.json`, renamed, re-detected or deleted under Settings → Machines.
- **Agent**: Claude Code, Codex, pi, ZCode, OpenCode and Hermes each count as one identity; several sessions of the same Agent share one avatar.
- **You**: identified by the local user name, and signed onto the notes you leave on tasks and the acceptance boxes you tick.
