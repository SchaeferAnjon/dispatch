# 常见问题与排错

> 这一页解决什么：每条按「现象 → 原因 → 怎么办」写。先用页面顶部的搜索框搜现象里的关键词。

## 打开应用是空的，或红色英文报错

**现象**：工作台空白，首次设置不出现，或者页面顶部一条红色的英文错误（`SyntaxError`、`bd: command not found`、`no beads database found`）。

**原因**：Dispatch 的逻辑在 Python CLI 里，应用本身不带解释器。它会依次找 Homebrew 和系统里的 Python（需要 **3.9 或更新**）；一个都找不到时显示「环境检查」页。另一种情况是依赖（bd、dolt、herdr）没装或没建任务板，这时界面顶部会有一条提示和「打开首次设置」按钮。

**怎么办**：

1. 看「环境检查」页上带 ✗ 的项，点「复制安装命令」，在终端里粘贴运行，装完回来点「重新检查」。想指定某个解释器：启动前设环境变量 `DISPATCH_PYTHON=/路径/python3`。全新 Mac 还没装 Xcode 命令行工具时，系统的 `python3` 和 `git` 只是占位，`xcode-select --install` 会把它们装上。
2. 重开 Dispatch，走首次设置第 1 步「装依赖」和第 3 步「任务板」。
3. 还是不行就在终端里跑 `python3 /Applications/Dispatch.app/Contents/Resources/cli/dispatch.py init status --json`，看具体报错。

## 读不到会话

**现象**：终端里 Agent 明明在跑，工作台或会话页没有它；或者会话页一直「索引中…」。

**原因**：可能是会话归到了别的项目名、Agent 记录路径不是默认位置、索引第一次要读完全部历史、或 CLI 根本没跑起来（见上一条）。

**怎么办**：

- 第一次打开要读完全部历史，等一两分钟；`dispatch index` 可以手动重建。
- 看 设置 → 项目 → 工作区根目录：不在这些目录下的会话按 git 根或文件夹归项目，可能出现在「其他目录与未归类」里，或者项目名是文件夹名。
- 会话页把 Agent 筛选设为「全部」，模式设为「最近」；零散会话在列表底部折叠着。
- OpenCode、ZCode、Hermes 的会话来自它们的数据库（`~/.local/share/opencode/opencode.db`、`~/.zcode/cli/db/db.sqlite`、`~/.hermes/state.db`），进程没开或 30 分钟内没写入就不算活会话，但历史仍可看。
- `dispatch list --local -q 关键词` 直接查索引。

## 会话状态不对：明明停了还显示「在跑」，或不显示「等你」

**现象**：会话列表的状态和终端里看到的不一致；工作台没有「等待确认」。

**原因**：在跑 / 等你的判断来自 Claude Code 的 hook 上报和 Herdr。没装 hook（首次设置第 4 步没勾 Claude Code）、或会话在 Warp / iTerm / Terminal 里跑而不在 Herdr 里，就只能凭转录文件的写入时间推断。

**怎么办**：跑一遍首次设置第 4 步；把会话「接进 Herdr」（会话页头部或右键）；确认 Herdr 在跑（`herdr` 命令存在，tmux 常驻）。

## 回复没送达

**现象**：点「发送」后显示「连接暂时不可用」「未确认」「送达状态未知」，或者原终端里没出现你的话。

**原因**：回复只投递给所选电脑上的原会话，而且 Herdr 终端必须同时匹配会话 ID 与前台进程；Agent 正在执行或等待权限确认时不会写入输入。Codex 桌面端依赖它当前版本的本地 IPC 接口，不兼容或会话没打开会失败。

**怎么办**：

- 看回复框上方的状态行：它说会话在哪。在别的终端里就点「接进 Herdr 再发」；原终端关了就「在电脑上恢复并发送」；正在跑就「排队发送」或「打断并发送」。
- 停在确认框上时先用上方的按键（⏎、y、1 …）把确认过掉。
- 「检查送达状态」重新查回执；同一条消息不会发两次。
- Codex 桌面端提示重新连接时，在桌面端里打开那段会话再试。
- 终端不是 Ghostty 时「跳到会话」只能给提示，回复仍然可以走 Herdr。

## 手机连不上

**现象**：扫码后「无法连接」，或设置页复制链接时报「网页版服务没在 … 上跑」。

**原因**：网页版由 `dispatch serve` 提供（端口 7799）。它需要一直在跑；当前版本的 .app 里没有打包安装常驻任务的脚本，`serve url` 检查到服务没跑就会报错，但二维码还是会画出来。另一个常见原因是手机没连 Tailscale，或电脑没装 Tailscale 时服务绑在局域网地址、手机不在同一 Wi‑Fi。

**怎么办**：

1. Mac 终端里跑 `dispatch serve`（前台，保持这个窗口），再扫码。
2. 想常驻：仓库 `app/scripts/serve-setup.sh` 会装一个 launchd 任务（标签 `dev.schaefer.dispatch-serve`）；从源码目录跑它一次即可。这是已知的待改进项，见 [已知限制](26-limits.md)。
3. 手机上确认 Tailscale 已连接、和 Mac 在同一 tailnet；没 Tailscale 就确保同一 Wi‑Fi。
4. 换了「手机版跑在」哪台机器后，要在手机上重新打开一次新链接。
5. 旧链接失效时重新扫码：令牌在 `~/tasks/.dispatch/serve.json`。

## 收不到手机推送

**现象**：Agent 回复了、等确认了，手机没响。

**原因**：三种之一：渠道没配（`BARK_KEY` / `NTFY_URL` 都没有，只会发 Mac 系统通知）；`dispatch serve` 没在跑（「Agent 回复了」「等你确认」由它每 20 秒检查一次）；Bark 或 ntfy App 没有通知权限，或 ntfy 没订阅那个主题。

**怎么办**：

1. 设置 → 手机通知：看「当前渠道：ntfy / Bark」是否出现；没有就填 key 或主题地址并保存。
2. 点「发一条测试通知」或终端 `dispatch notify "测试" "正文"`：手机收到说明渠道通了。
3. 确认 `dispatch serve` 在跑（见上一条）。`dispatch notify-watch --json` 手动跑一趟，看 `sent` 数和 `skipped` 原因。
4. 四个事件开关是否打开；超过 6 小时的旧回复不推；第一次开启不回放历史；定时会话和另一台机器上的会话不推。
5. 手机系统设置里给 Bark / ntfy 通知权限；ntfy 在 App 里订阅同一个主题。

## 额度显示为空、「暂无可用额度数据」或数据较旧

**现象**：额度页某个 Agent 没有数字，或提示数据较旧。

**原因**：Claude Code 的额度来自官方用量接口，需要读本机的登录态（钥匙串里的 Claude Code 凭据，第一次会弹「python3 想访问钥匙串」，拒绝后就读不到）；Codex、ZCode 读各自的本地状态文件，没登录或没装就没有。没装的 Agent 也会列出来但没数据。

**怎么办**：钥匙串弹窗选「始终允许」；确认该 Agent 已登录并至少用过一次；「刷新额度」；只想看有数据的就收起「暂无额度数据」。两台机器数字对不上时看卡片提示，同一账号两边应一样。

## 总结不生成、报 Key 错误、Zhipu 或 OpenAI Key 怎么配

**现象**：项目「现状」空着、会话没有总结、「等我」的未读摘要一直「正在写…」，或报「缺 Key」「总结已在设置里关闭」。

**原因**：总结用的模型取自 设置 → 会话 → 总结用的模型：订阅模型走 Claude Code 订阅（需要 `claude` 命令已登录），API Key 模型用 `dispatch env` 里的 `ZHIPU_API_KEY`、`KIMI_API_KEY`、`MINIMAX_API_KEY`、`OPENAI_API_KEY`。DeepSeek 的 Key 存在也不会被自动选用（代码里停用了）。对应用途在用途表里关了也不会生成。

**怎么办**：

- 设置里选一个模型；显示「缺 Key」就在下面的输入框粘贴 Key 保存；或终端 `echo "sk-…" | dispatch env set ZHIPU_API_KEY --stdin --note "总结"`。
- 智谱走 Coding Plan 端点时注意用对的 Key 和端点，按量端点会报余额不足。
- 检查用途表里对应开关是否打开；`dispatch summarize providers` 看哪些可用，`dispatch session-summary run <key> --force` 手动跑一次看报错。

## 更新失败

**现象**：「检查更新」报错，或「更新到 vX」后提示失败。

**原因**：GitHub 接口限流或网络不通；更新器只替换 `/Applications/Dispatch.app`，装在别处的会被当作没装；替换完成后重启网页服务这一步失败会被报成更新失败（其实应用已换好）；Intel 机器没有对应包。

**怎么办**：稍后再试或去 [Releases](https://github.com/SchaeferAnjon/dispatch/releases) 手动下载 zip 覆盖；应用放在 `/Applications`；提示失败后看设置页版本号，如果已经是新版就没问题。终端里 `dispatch update check --json` 看详细错误。

## Gatekeeper：「无法打开，因为无法验证开发者」

**现象**：第一次打开被拦。

**原因**：包没有 Apple 开发者签名和公证。

**怎么办**：`xattr -dr com.apple.quarantine /Applications/Dispatch.app`，或 系统设置 → 隐私与安全性 → 「仍要打开」。每次手动更新后可能要再做一次（应用内更新会自动清除隔离标记）。首次运行 CLI 后 .app 里会生成 `__pycache__`，这会让 `codesign --verify` 报错，但不影响使用；只是自动化、通知等权限可能会再问一次。

## Herdr 不在跑

**现象**：派活、新建会话、「接进 Herdr」、终端按钮报错；等待确认不显示。

**原因**：Herdr 依赖 tmux 常驻会话；没装、没起，或首次设置第 1 步失败。

**怎么办**：`brew install herdr tmux`；重跑首次设置第 1 步和第 4 步（第 4 步会确认 Herdr 在跑并给出结果）；终端里 `herdr` 看它是否能列出标签。终端应用只对 Ghostty 有自动切换，其他终端能用但「跳到会话」只给提示。

## 两台电脑同步失败

**现象**：接入后任务不一致、「每 2 分钟双向同步」没生效、迁移卡在「预检中」、或另一台一直「暂时连不上」。

**原因**：ssh 不通（远程登录没开、公钥没放、Tailscale 离线或在睡眠）；Dolt 远程 API 端口没通；两边同时改同一任务产生冲突；迁移预检发现 Git 冲突。

**怎么办**：

1. 枢纽上确认 系统设置 → 通用 → 共享 → 远程登录已开；两边 Tailscale 在线。终端里 `ssh 用户名@地址 echo ok` 应该免密返回。
2. 设置 → 机器 → 「重新检测」；首次设置第 3 步「检查一次」反向连接。
3. `dispatch rules status` 和 `dispatch init status --json` 看板和规则状态；单机时 `rules sync` 会以「不用同步」退出，这不是错误。
4. 迁移有冲突时先在两边提交或 stash，再迁；确认要覆盖对方就 `--force`。
5. 迁移后另一台不标记「已迁往」：局域网接入（无 Tailscale）时不会自动标记，手动 `dispatch moves mark <id> --to <机器>`。

## 规则同步后 Agent 没变化

**现象**：改了 GLOBAL.md 并同步，正在跑的会话还是老规矩。

**原因**：修改规则不会重载已有会话。

**怎么办**：新开会话；`dispatch rules status` 确认每个入口的托管块已更新。

## 项目名不对，或一个项目被拆成两个

**现象**：同一份代码在两个项目名下，或项目名是路径的一截。

**原因**：归属按规则解析：手动关联 > 家目录 > 工作区根目录的直接子文件夹 > 路径里出现任务板已知的项目名 > git 根 > 文件夹名。子目录里开的会话可能归到子目录名。

**怎么办**：把代码所在的父目录加进工作区根目录；对已有会话右键「关联项目…」手动指定；任务用 `project:<名>` 标签归类。改显示名不影响归类。

## 编辑被拦：「另一个会话 30 分钟内改过这个文件」

**现象**：Claude Code 里改文件被 hook 拒绝。

**原因**：编辑互斥 hook（首次设置第 4 步装的）在同一文件 30 分钟内被另一个会话改过时拒绝，防止两个 Agent 互相覆盖。单机 `/clear` 或开第二个窗口也会触发一次。

**怎么办**：`dispatch editing` 看谁在改；确认没人在改就再试一次或稍等；不想要这个保护可以从 `~/.claude/settings.json` 的 hooks 里删掉 edit-guard 两条。

## 台式机屏幕不休眠

**现象**：Mac mini / iMac 上装了 Dispatch 后屏幕不再自动锁定。

**原因**：没有电池的机器上 Dispatch 用 `caffeinate` 阻止休眠，目前没有开关。

**怎么办**：不用时退出 Dispatch；见 [已知限制](26-limits.md)。
