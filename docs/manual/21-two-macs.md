# 两台电脑

> 这一页解决什么：第二台 Mac 怎么接进来、什么会同步、项目和会话怎么搬到另一台、按机器筛选、一台离线时是什么表现。

## 接入

第一台完成首次设置后就是**枢纽**：任务板（Dolt 数据库）、规则、技能都在它上面。第二台：

1. 在枢纽上打开 系统设置 → 通用 → 共享 → **远程登录**（接入要 SSH）。
2. 第二台装好 Dispatch，首次设置第 3 步选「已有一台电脑装了 Dispatch」，填枢纽的 `用户名@地址`：同一 Wi‑Fi 用局域网 IP，出门用 Tailscale 地址（页面可以从 Tailscale 列表里选）。在 设置 → 机器 里也能点「接入另一台电脑…」。
3. 填一次枢纽的登录密码（只用一次，不保存），Dispatch 把本机公钥放过去，之后两边免密互访；不想给密码，点「让本机 Agent 代劳」，让 Agent 在终端里做。
4. 点「打通并接入」。接入后页面显示「已接入 <名字>，每 2 分钟双向同步」。
5. 「检查一次」枢纽能否反向连回本机（枢纽合并这台的会话需要），失败时页面会说该去哪打开远程登录。

本机已经有板了想改成接入：第 3 步里「改为接入另一台电脑的任务板…」，本机的板会停掉并改名保留（`~/tasks/.beads.retired-日期`），不会删除。

## 什么会同步

| 内容 | 方式 |
|:--|:--|
| 任务板（任务、成果、知识库、设置、项目收藏与归档） | 每 2 分钟双向同步（Dolt 远程 API） |
| 共同规则 GLOBAL.md、FACTS.md、PROFILE.md | `dispatch rules push\|pull\|auto`，应用定时器每半小时对一次 |
| 技能池 | 首次设置第 5 步从枢纽复制；之后 `dispatch rules` 系列同步 |
| 会话记录 | 不复制。各在各的机器上，Dispatch 通过 ssh 读另一台的列表和详情（远端列表上限 200 条） |
| 密钥（dispatch env） | 不同步，各机各自配 |
| 发送回执、手机令牌 | 不同步 |

侧栏顶部出现「全部 / 机器 A / 机器 B」：选一台，任务、会话、额度、统计都只看它；「全部」合并。手机顶部也有同样的选择。「Agent 状态」页顶部的机器条能派活、看屏幕。

## 迁移项目

项目页头部「迁移到 <机器>」：

1. **预检**：Git 与文件差异、缺哪些工具；有冲突会拒绝（`--force` 才覆盖对方改动）。
2. 确认后把目录（含未提交改动）、Git 历史、正在跑的会话和全部历史记录搬过去，那边直接续上。
3. 迁移在后台跑，项目卡片和项目页上有进度条（切页面、刷新都不丢）；`dispatch project-moves` 看进度。
4. 完成后项目「所属电脑」变成那台，新建会话默认开在那里。

命令行：

```sh
dispatch project <项目名> --move-to <机器 id 或名字> [--dry-run] [--background] [--keep-original]
dispatch project <项目名> --owner <机器|local|none>     # 只记录归属，不搬文件
```

## 迁移单段会话

会话右键 → 「迁移到 <机器名> 接着做」，或：

```sh
dispatch move <会话 id 前缀> --to <机器> [--prompt "额外交代"] [--no-files] [--dry-run]
```

对方接手后会话列表里两边各有一份：原来的标「已迁往 <机器>」，新的标「从 <机器> 迁来」；原会话默认停掉（`--keep-original` 不停）。支持 Claude Code 和 Codex；pi 的会话存在自己的库里，暂不迁移。`dispatch resume <id> --on <机器>` 指定在哪台恢复。

## 离线时的表现

- 工作台顶部写「<机器> 暂时连不上」，保留已读取的记录；另一台的会话打开时提示「这段会话在 <机器> 上，现在连不上那台电脑（它的 Tailscale 离线或在睡眠）；等它上线后会自动读到」。
- 新建会话的运行电脑下拉里离线的机器不可选；配置页（技能、规则、记忆）选离线机器时显示原因（「本机 Tailscale 没开」或「<机器> 离线」）。
- 任务板：各自本地可读写，联网后双向合并；同一任务两边都改可能产生 Dolt 冲突，看 [排错](24-troubleshooting.md#两台电脑同步失败)。
- 额度：同一账号在两台上的额度共享不累加；一边数据过期时卡片会提示。

## 管理机器

设置 → 机器：改名（同步推给已知的机器）、重新检测、删除。`dispatch hosts` 列出这台和其他的、虚拟网类型、远程桌面能力和推荐方式；`dispatch hosts rename <id|local|名字> <新名字>`。`dispatch --host <id> <任意子命令>` 在另一台上跑命令。
